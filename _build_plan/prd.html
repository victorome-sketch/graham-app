Graham Screener

A checklist app: give it a US stock ticker and it shows whether the stock meets Benjamin Graham's seven defensive-investor criteria from The Intelligent Investor (Ch. 14), plus how the current price compares to the Graham Number. Every verdict is a fact about the company's financials — pass or fail against a written rule. Never a prediction, never a buy/sell recommendation. A personal, single-user study tool applying one book's published criteria; not financial advice. Built on the Build New starter (Rails 8, React 19, Inertia, PostgreSQL) across three milestones.

Rails 8 React 19 Inertia PostgreSQL Tailwind v4 Build New starter

What the app does

  • Ticker lookup

    Enter one US ticker; the app fetches fundamentals and pre-fills the analysis form.

  • Editable form with provenance

    Every input is hand-editable and tagged api or manual; missing API data never blocks an analysis.

  • Graham rules engine

    Seven pass/fail/N-A verdicts against the defensive-investor criteria, each shown with the actual numbers behind it.

  • Graham Number & margin

    Graham's fair-value ceiling shown next to the current price with a margin % — displayed as information, never a signal.

  • Saved history

    Every analysis is saved as a frozen snapshot; browse past runs and re-run any ticker with fresh data.

  • Configurable threshold

    The revenue threshold for criterion 1 is a setting (default ≈ $700M), not a constant.

The rules — the heart of the app

# Rule Check Data needed
1 Adequate size Revenue ≥ threshold (Graham's $100M in 1973 ≈ $700M today; configurable setting) Latest revenue
2 Strong financial condition Current ratio ≥ 2. N/A for financial companies (banks, insurers) — never failed for them Current assets & liabilities
3 Earnings stability Positive EPS every year, last 10 years 10y EPS history
4 Dividend record Dividend paid every year, last 20 years 20y dividend history
5 Earnings growth EPS growth ≥ 33% over 10 years, using 3-year averages at each end 10y EPS history
6 Moderate P/E Price ≤ 15 × average EPS of last 3 years Price + 3y EPS
7 Moderate P/B P/B ≤ 1.5, or P/E × P/B ≤ 22.5 Price + book value/share

Graham Number

Graham Number = √(22.5 × EPS × BVPS)

Shown next to the current price with a margin: (Graham Number − Price) / Graham Number. Positive margin = trading below Graham's fair-value ceiling. Information only, never a signal.

Limitations shown in the UI

Thresholds are from the 1970s — a strict P/E ≤ 15 rejects nearly every modern growth company. The app says "fails Graham's rules," never "bad stock." This note is visible on the results screen, alongside the financial-company N/A rule and the configurable revenue threshold.

Out of scope (v1)

  • Buy/sell recommendations or aggregate scores — the output is "X of 7 criteria met," never "buy this." Verdicts about facts, not forecasts.
  • Market-wide screening — v1 analyzes one ticker at a time; it does not scan for candidates.
  • Enterprising-investor criteria — v1 is the defensive checklist only.
  • Watchlists, scheduled re-checks & alerts — re-running from history is manual and deliberate.
  • Charts & portfolio tracking — this checks stocks against rules; it doesn't track holdings or draw pictures.
  • Non-US stocks & currencies — US-only keeps the data source consistent.
  • Multi-user accounts & public signup — one person, one account behind the Build New starter's existing login; opening signup to others, teams, and sharing are all out.
  • Ticker autocomplete, CSV upload, multiple data providers — one ticker field, one API, manual entry as the only fallback.

External integrations

Alpha Vantage

Fundamentals data

Supplies company financials (revenue, EPS history, dividend history, book value, price) when a ticker is entered. Free tier: ~25 requests/day with full-length annual histories — enough for one-ticker-at-a-time use. The provider must remain swappable; manual entry is the first-class fallback for anything it can't supply. Fundamentals fetched within the last 90 days are reused rather than re-fetched.

Credentials needed

  • Free Alpha Vantage API key (email signup at alphavantage.co)

Milestones

1

Rules engine — manual entry only

Proves the core: a form for all inputs feeds the rules engine and produces the full checklist screen. No API, no saving. Testable against worked examples from the book.

What gets built

  • A manual input form for everything the 7 criteria and Graham Number need (ticker, company name, financial-company flag, price, and all financial inputs), with required fields clearly flagged until filled
  • The rules engine: all 7 defensive-investor checks, including criterion 2 marked N/A (not failed) for financial companies
  • The checklist results screen: each rule in plain language with the actual numbers used and its pass/fail/N-A verdict; the "X of 7 met" count; Graham Number vs. price with margin %; the limitations note visible on-screen
  • The revenue-threshold setting (default ≈ $700M), editable by extending the starter's existing Settings page

Not in this milestone

  • Any API fetching — every number is typed in by hand
  • api/manual provenance tags (everything is manual here; tags arrive with the API in M2)
  • Saving analyses or any history

Done when: a worked example from The Intelligent Investor can be typed in by hand in the browser and produces the correct 7 verdicts, the correct X-of-7 count, and the correct Graham Number and margin.

2

API fetch & caching

Ticker lookup pre-fills the form from Alpha Vantage. Manual entry stays first-class — the API assists, never gates.

What gets built

  • Entering a ticker fetches fundamentals from Alpha Vantage and pre-fills the form; fetched fields are tagged api, gaps are left blank and flagged
  • Every field stays hand-editable; editing an api value flips its tag to manual, so provenance is always visible and truthful
  • If the API fails or the ticker isn't found, a plain message appears and the form works fully manually — never a dead end
  • Fundamentals fetched within the last 90 days are reused rather than re-fetched — repeat lookups don't spend API calls

Not in this milestone

  • Saved history or re-run
  • Ticker autocomplete or search
  • A second data provider — one API, swappable later

Done when: entering a real ticker pre-fills the form with tagged API data, gaps can be filled by hand, the checklist runs, and looking the same ticker up again reuses the stored data instead of calling the API.

3

Saved history

Analyses become permanent records: browse them, reopen them intact, re-run any ticker fresh.

What gets built

  • Every completed analysis is saved automatically as a frozen snapshot — inputs, provenance tags, verdicts, numbers, Graham Number
  • A history page listing analyses newest-first: ticker, company, date, X of 7, margin
  • Opening a past analysis shows its full checklist exactly as it was — past analyses are never editable
  • A "Re-run" action starts a fresh analysis for that ticker with fresh data, creating a new record alongside the old
  • Analyses can be deleted

Not in this milestone

  • Search or filters on history
  • Notes or annotations on analyses
  • Side-by-side comparison of two analyses
  • Tracking price changes since an analysis was run

Done when: after running analyses on a few tickers, they appear newest-first in history, an old one reopens exactly as it was, re-running creates a second record beside it, and deleting removes one.
